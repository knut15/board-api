# 검증 스크립트 규약

스크립트는 스크래치패드(`<scratchpad>/`)에 둔다. 레포에 커밋하지 않는다 —
실행 환경에 묶인 값(포트·경로·psql 위치)이 박혀 있다.

## 세 종류를 섞지 않는다

| 종류 | 파일 | 하는 일 | 데이터 |
|---|---|---|---|
| 회귀 | `verify.sh` | 앞 단계들의 동작이 그대로인지 | **지운다** (시작할 때 TRUNCATE) |
| 게이트 | `gateN.sh` | 이번 단계의 "이러면 끝" | 지운다 |
| 성능 | `bench.sh` | 응답 시간·쿼리 수·실행 계획 | **건드리지 않는다** |

**성능을 재는 중에 회귀를 돌리지 않는다.** 시드가 사라진다.

## 공통 규칙

1. **멱등성** — 몇 번 돌려도 같은 결과. 계정이 이미 있으면 로그인, 없으면 가입하는 식으로 짠다.
   또는 시작할 때 비우되 **그 사실을 파일 첫 줄과 이름에 적는다.**
2. **기대값을 먼저 쓴다** — `chk "설명" <기대> "$(code …)"` 형태. 실제값을 보고 기대값을 맞추지 않는다.
3. **응답 형태도 검사한다** — 상태 코드만 보면 놓친다. 에러 봉투의 키·누출 문자열까지 본다.
4. **측정은 중앙값** — 워밍업 1회를 버리고 15회를 재 중앙값·최소·최대를 남긴다.

## 형식

```bash
chk() { if [ "$2" = "$3" ]; then printf "  ok   %-44s %s\n" "$1" "$3"; pass=$((pass+1));
        else printf "  FAIL %-44s 기대 %s 실제 %s\n" "$1" "$2" "$3"; fail=$((fail+1)); fi; }
code() { curl -s -o /tmp/body.json -w "%{http_code}" "$@"; }
```

끝에 `통과 N · 실패 M` 을 찍는다. 보고에 그 수치를 그대로 옮긴다.

## 이 레포에서 실제로 난 사고 셋

### 1. 스크립트를 고치다 JSON 을 깨뜨렸다

회귀 40건 중 20건이 한꺼번에 실패했다. **서버는 멀쩡했고 내가 따옴표를 깨뜨린 것이었다.**

- 여러 건이 **한꺼번에** 실패하면 서버보다 스크립트를 먼저 의심한다.
- 고친 뒤 `bash -n <파일>` 로 문법을 확인한다.
- `$(...)` 안에서 중첩 따옴표를 쓰지 않는다. JSON 은 작은따옴표로 통째로 감싼다.

### 2. 회귀 스크립트가 시드를 지웠다

글 1만 건을 넣고 회귀를 돌리자 전부 사라졌다. 시작할 때 `TRUNCATE` 하도록 **내가 만들어 둔 것**이다.
측정이 끝난 뒤라 잃은 것은 없었지만, 순서가 반대였으면 다시 재야 했다.

### 3. 로그를 truncate 했더니 grep 이 0 을 냈다

`: > $S/q.log` 로 비우면 이미 열려 있는 파일 오프셋이 그대로라 앞쪽이 **NUL 바이트**로 채워진다.
`grep` 이 바이너리로 판정해 개수를 세지 않는다.

- 로그는 비우지 말고 **오프셋으로 잘라 읽는다**(`wc -c` → `tail -c +N`).
- 굳이 grep 해야 하면 `grep -a`.

## 측정이 실패를 보고했다고 코드가 틀린 것은 아니다

6단계에서 JWT 서명의 마지막 글자를 바꾼 토큰이 `401` 이 아니라 `200` 을 받았다.
서버를 의심했지만 **검사가 틀린 것**이었다 — HS256 서명 32바이트는 base64url 43자이고
마지막 글자는 실제 비트를 2개만 담아, 여러 글자가 같은 바이트로 디코드된다.

검사가 실패하면 **검사 자체를 한 번 의심한다.** 대조 실험으로 가른다.
