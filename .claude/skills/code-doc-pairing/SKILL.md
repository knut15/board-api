# 코드와 문서를 짝지어 두기

<!-- forbidden-words: allow — 금지어 규칙 자체를 인용하는 문서다. -->

이 레포는 교육용이다. **코드 파일마다 해설 문서가 하나씩 있고, 서로를 가리킨다.**

```
server/src/store/posts.ts   첫 줄: // 문서: docs/code/store-posts.md · 커리큘럼 3.4 · 4.5 · 7.3
docs/code/store-posts.md    첫 줄: # server/src/store/posts.ts
```

## 문서 골격 — 그대로 지킨다

```markdown
# server/src/<경로>

> 커리큘럼 <항목 번호들> · 짝: `server/src/<경로>`

## 무엇을 하는 파일인가      2~4줄
## 코드를 따라 읽기          발췌 + 왜. 전체 복붙 금지
## 왜 이렇게 했는가          대안과 트레이드오프 2~3
## N단계에서 무엇이 바뀌었나  (단계가 지날 때마다 절을 추가한다)
## 직접 해 볼 것             실험 2~3, "무엇을 바꾸고 → 무엇을 확인한다"
## 다음 단계에서 어떻게 바뀌는가
```

**"N단계에서 무엇이 바뀌었나" 는 역사 기록이라 지우지 않는다.** 단계가 늘면 절이 쌓인다.
길어지면 오래된 절의 문장을 줄이되 내용을 없애지 않는다.

## 문체

- **한글.** 코드·식별자·SQL·에러 코드·명령어는 원문 그대로.
- 문서체 — "~한다", "~이다". 존댓말·이모지 금지.
- **`벽` 이라는 글자를 쓰지 않는다.** 어떤 뜻으로도.
- **확인하지 않은 값을 쓰지 않는다.** 측정값은 실제로 잰 것만.

## 검사 — 문서를 고친 뒤 반드시 돌린다

```bash
cd /Users/kim/Workspace/board-api

# 1. 코드 → 문서 (dangling 0 이어야 한다)
for f in $(find server/src web/src -name '*.ts' -o -name '*.tsx' | grep -v node_modules); do
  doc=$(head -1 "$f" | sed -n 's|^// 문서: \([^ ]*\).*|\1|p')
  [ -n "$doc" ] && [ ! -f "$doc" ] && echo "DANGLING $f -> $doc"
done; echo "검사 끝"

# 2. 문서 안 상대 링크
cd docs && for f in $(find . -name '*.md'); do d=$(dirname $f)
  grep -oE '\]\([^)h][^)]*\)' $f | tr -d '])' | sed 's|^(||' | while read -r l; do
    [ -e "$d/$l" ] || echo "DANGLING $f -> $l"; done; done; echo "검사 끝"; cd ..

# 3. 금지어
grep -rln "벽" docs/ || echo "0건"

# 4. 골격
for f in docs/code/*.md; do printf "%-32s %s\n" "$(basename $f)" "$(grep -c '^## ' $f)절"; done
```

## 서브에이전트에게 맡길 때

문서 여러 개를 동시에 고칠 때는 파일 소유권을 나눠 병렬로 띄운다.
**`doc-writer` 에이전트(`.claude/agents/doc-writer.md`)를 쓴다.** 그 정의가 이 문서를 읽고 시작한다.

고정값은 에이전트 정의와 이 문서가 들고 있다. **브리핑에는 매번 달라지는 셋만 넣는다.**

1. **담당 파일 목록과 짝이 되는 코드** — 표로. 어느 문서가 어느 코드의 짝인지.
2. **실측값 표** — 내가 잰 값을 전부. 에이전트는 스스로 재지 않는다(서버·DB 가 내 작업과 충돌한다).
3. **무엇이 바뀌었나** — 코드의 어느 부분이 어떻게 달라졌는지 항목으로.

줄 수 상한도 브리핑이 정한다. 단계가 쌓이면 110 → 125 → 135 → 140 으로 올린다.

### 브리핑이 놓치면 생기는 일

- 실측값을 안 주면 그럴듯한 숫자를 지어낸다.
- "발췌를 소스에서 다시 따온다" 를 안 쓰면 옛 코드를 그대로 둔다.
- 작업 중 소스가 다음 단계로 넘어가면 에이전트가 **옛 코드 기준 문서**를 만든다.
  그럴 때는 보고를 읽고 어긋난 곳만 다음 라운드에서 고친다.

### 에이전트 보고에서 챙길 것

에이전트가 짚은 불일치는 **대개 진짜다.** 이 레포에서 실제로 나온 것들:

| 보고 | 확인 결과 |
|---|---|
| `views.ts` 주석이 "20개면 40번" 인데 실측은 22 | 맞았다. Prisma 가 작성자 조회를 `IN` 으로 묶는다 |
| `P2025` 번역이 저장소와 에러 핸들러 두 곳에 있다 | 맞았다. 저장소 쪽을 걷어냈다 |
| argon2 파라미터 표기가 실제 출력과 다르다 | 표기만 달랐다. 기능은 정상 — **재 보고 확인했다** |
| `throw` 가 6개가 아니라 5개다 | 맞았다. 내가 브리핑한 뒤 코드가 바뀌었다 |

보고를 그대로 믿지도, 무시하지도 않는다. **직접 재 보고 판정한다.**
