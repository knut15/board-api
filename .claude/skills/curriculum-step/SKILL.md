# 커리큘럼 한 단계 돌리기

출처는 아티팩트 "게시판 API 서버, 설계부터 배포까지"
(<https://claude.ai/artifact/WffCicExjmUU5R7yfvba1H>) 의 9단계다.

**게이트를 못 채웠으면 다음 단계로 가지 않는다.** 날짜가 아니라 게이트가 기준이다.

## 0. 시작 전에 확인할 것

| 확인 | 명령 |
|---|---|
| DB 가 떠 있나 | `pnpm --filter board-api-server db:up` |
| 서버가 뜨나 | `curl -s localhost:4000/health` |
| 지금 어디까지 왔나 | `docs/00-overview.md` 의 "읽는 순서" 표 마지막 줄 |
| 앞 단계 회귀가 통과하나 | `bash <scratchpad>/verify.sh` |

앞 단계 회귀가 깨진 채로 다음 단계를 시작하지 않는다. 원인이 섞여서 못 찾는다.

## 1. 설치가 필요하면 먼저 가른다

- **커리큘럼이 도구를 지정했으면** 한 줄 예고하고 설치한다 (zod, argon2, jose, Prisma).
- **기계 상태를 바꾸는 것**은 선택지와 함께 묻는다 (VM 생성, 전역 설치, 수백 MB 내려받기).
- 버전은 **`latest` 를 믿지 않는다.** 이 프로젝트에서 `pnpm add prisma` 의 `latest` 가
  릴리스 후보(8.0.0-rc)를 가리켰다. 설치 직후 `node -e "require('<pkg>/package.json').version"` 으로 확인한다.

## 2. 구현

바꾼 파일마다 첫 줄 주석에 짝이 되는 문서를 적는다 — `// 문서: docs/code/<이름>.md · 커리큘럼 N.x`.
새 파일이면 문서도 새로 만들어야 한다(code-doc-pairing).

## 3. 게이트 검사를 먼저 만든다

커리큘럼의 "이러면 끝" 항목을 **그대로 검사 항목으로 옮긴다.** 구현이 끝난 뒤에 만들면
이미 통과하는 것만 검사하게 된다. 스크립트 규약은 verification-scripts 를 따른다.

## 4. 실측값을 수집한다

단계 문서에 넣을 숫자다. **없는 값을 문서에 쓰지 않는다.**

| 무엇 | 어떻게 |
|---|---|
| 쿼리 수 | `PRISMA_LOG=query` 로 서버를 띄우고 로그를 오프셋으로 잘라 센다 |
| 실행 계획 | `psql -c 'EXPLAIN ANALYZE …'`, 전후를 모두 남긴다 |
| 응답 시간 | 워밍업 1회 버리고 15회 중앙값 |
| 상태 코드 분포 | `grep -ohE 'fail\(res, [0-9]{3}' src/routes/*.ts \| …` |
| DB 상태 | `psql -tAc 'select count(*) …'` |

성능을 재기 전에 **회귀 스크립트를 돌리지 않는다.** 그 스크립트는 DB 를 비운다.

## 5. 회귀

앞 단계들의 검사를 다시 돌린다. 인증 방식이 바뀌었다면 헤더만 갈아 끼우고 기대값은 그대로 둔다 —
기대값을 바꾸고 싶어지면 그건 명세가 바뀐 것이고, 명세 문서부터 고쳐야 한다.

## 6. 단계 문서

`docs/0N-<주제>.md`. **번호는 읽는 순서이고 커리큘럼 단계와 다르다**(04·05 는 클라이언트 문서다).
문서 첫머리에 그 사실을 적는다.

담을 것:

1. 무엇이 어디로 갔는지 (전/후 표)
2. 커리큘럼 항목별 본문 (N.1 … N.7)
3. **정한 것과 그 이유** — 커리큘럼이 "정하라" 고만 한 것들
4. 통과 조건 체크박스 + **검증 기록 표**(무엇을·어떻게·결과)
5. **겪은 것** — 틀렸던 판단, 헛다리, 환경 문제
6. 남은 것 · 다음 단계

## 7. 명세 동기화

코드가 명세와 어긋났으면 **명세를 고치는 것이 순서다.** 고친 사실을 단계 문서에 적는다.

| 파일 | 언제 고치나 |
|---|---|
| `docs/02-api.md` | 엔드포인트·상태 코드·쿼리 파라미터가 바뀌면 |
| `server/openapi.yaml` | 위와 같음. 고친 뒤 `ruby -ryaml` 로 파싱과 `$ref` 를 검사한다 |
| `docs/00-overview.md` | 읽는 순서 표, 레포 구조 주석, "정해 둔 것" 표 |
| `docs/scenarios.md` | 완성 시나리오를 실제로 돌렸으면 검사 기록에 날짜와 결과 |

## 8. 완료 보고

- 만든 것과 경로
- **검증한 것과 수치** — "통과했습니다" 가 아니라 무엇을 어떻게 돌려 어떤 값이 나왔는지
- 커리큘럼과 어긋난 것 (있으면 숨기지 않는다)
- 못 한 것 · 불확실한 것

## 이 프로젝트에서 실제로 어긋난 것

다음 단계에서 같은 함정을 밟지 않도록 적어 둔다.

| 단계 | 커리큘럼이 말한 것 | 실제 |
|---|---|---|
| 4.5 | "라우터는 한 줄도 건드리지 않는다" | 3단계 저장소가 동기라 전부 async 가 됐다 |
| 4.7 | "글 삭제 + 댓글 정리를 트랜잭션으로" | 4.3 에서 CASCADE 를 고른 순간 그 자리가 사라졌다 |
| 6.6 | "소유권 검사 5곳" | 이 설계에서는 3곳뿐이다 |
| 7.6 | "가장 인상적인 숫자가 여기서" | DB 시간은 33배, HTTP 는 1~2ms. 이 규모의 병목은 DB 가 아니었다 |

어긋나면 **커리큘럼을 따르는 시늉을 하지 말고 무엇이 왜 다른지 적는다.** 그게 더 값지다.
