# server/src/env.ts

> 커리큘럼 9.1 · 짝: `server/src/env.ts`

## 무엇을 하는 파일인가

환경변수를 읽고 **형식까지** 검증해 타입이 붙은 `env` 객체 하나를 내보낸다.
하나라도 어긋나면 이유를 한 줄씩 찍고 `exit 1` 로 죽는다 — 서버가 30분 돌다가 `undefined` 를
만나는 것보다 뜨지 않는 쪽이 낫다. 여섯 값의 검사 규칙은 [11-operations.md](../11-operations.md) 9.1 의 표에 있다.

## 코드를 따라 읽기

### `.env` 는 있으면 읽고 없으면 넘어간다

```ts
if (existsSync(".env")) process.loadEnvFile(".env");
```

`process.loadEnvFile` 은 Node 에 들어온 기능이라 `dotenv` 를 설치하지 않는다. `existsSync` 로 먼저 보는
이유는 파일이 없을 때 `loadEnvFile` 이 던지기 때문이다 — 배포 환경에서는 플랫폼이 환경변수를 직접 주입하므로
**파일이 없는 것이 정상**이다. `.env` 를 치우고 환경변수만 주입해 띄워 봤고 정상 기동, `/health` 200 이었다.

경로가 상대 경로인 것에 주의한다. 프로세스의 현재 디렉터리를 기준으로 찾으므로 `server/` 에서 실행해야 한다.

### 스키마가 곧 명세다

여섯 값을 객체 하나로 묶어 한 번에 본다. 규칙이 코드 한 줄에 다 보이는 것이 요점이다.

```ts
  JWT_SECRET: z.string("반드시 있어야 합니다.").min(32, "32자 이상이어야 합니다. openssl rand -hex 32"),
```

`min(32)` 가 이 파일에서 제일 값을 하는 조각이다. 짧은 키는 무차별 대입으로 뚫리고, 그때 벌어지는 일은
"토큰이 위조된다" 다. 메시지에 `openssl rand -hex 32` 를 적어 둔 것은 읽는 사람이 **고치는 방법까지**
같이 받게 하려는 것이다(그 명령의 결과는 64자다).

```ts
  PORT: z.coerce.number("숫자여야 합니다.").int().min(1).max(65535).default(4000),
```

환경변수는 언제나 문자열이라 `coerce` 가 필요하다. 쿼리 파라미터에서는 `coerce` 를 일부러 피했는데
(`routes-posts.md`) `""` 가 `0` 이 되기 때문이다. 여기서는 `min(1)` 이 그 `0` 을 걸러 내므로 써도 된다.
`default(4000)` 덕분에 로컬에서는 `PORT` 없이 뜬다.

`DATABASE_URL` 은 `z.url()`, `NODE_ENV`·`LOG_LEVEL` 은 `z.enum(...)`, `CORS_ORIGIN` 만 `.optional()` 이다.
마지막 하나가 선택인 이유는 8단계 구조에서 브라우저가 Express 를 직접 부르지 않아서다(8.1).

### 틀렸으면 한 줄씩 찍고 나간다

```ts
  console.error("환경변수가 올바르지 않습니다:");
  for (const issue of parsed.error.issues) {
    console.error(`  ${issue.path.join(".") || "(root)"} — ${issue.message}`);
  }
  process.exit(1);
```

`safeParse` 라 던지지 않는다. `issues` 를 **전부 돌아** 한 줄씩 찍는 것이 요점이다 — 하나씩 던지면
고치고 다시 띄우기를 빠진 개수만큼 반복한다. 아무것도 없이 띄우면 두 항목이 한꺼번에 나온다.

`console.error` 인 것에 이유가 있다. **이 시점에는 로거가 없다** — `logger.ts` 가 `env` 를 import 하므로
로거보다 이 파일이 먼저 평가된다. 여기서 `logger` 를 쓰려 하면 순환이 된다.

`process.exit(1)` 은 플랫폼이 **실패로 인식하게** 하려는 것이다. `0` 으로 나가면 정상 종료로 보인다.

### `env` 를 import 하는 것이 곧 순서다

```ts
export const env = parsed.data;
export type Env = typeof env;
```

실패하면 위에서 프로세스가 나가므로 여기 오면 `parsed.data` 의 타입이 좁혀진다. 받는 쪽은
`string | undefined` 가 아니라 `string` 을 본다 — `store/prisma.ts` 의 `!` 단언과 `auth/tokens.ts` 의 재검사가 함께 사라졌다.

그리고 **다른 모듈은 `process.env` 를 직접 읽지 않는다.** `env` 를 import 한다는 것이 곧 "검증이 끝난
뒤에 쓰겠다" 는 선언이라, 아래 6단계에서 겪은 로드 순서 문제가 구조적으로 없어졌다.

## 왜 이렇게 했는가

1. **배열 + `filter` 에서 zod 로 옮긴 것.** 6단계 판은 "있느냐" 만 봤다. 있기만 하고 틀린 값
   (`PORT="팔천"`, 16자짜리 `JWT_SECRET`)은 그대로 통과했고, 그런 값은 훨씬 뒤에서 이상한 모양으로 터진다.
   검증 라이브러리는 요청 바디 때문에 이미 들어와 있으므로 새 의존성이 아니다.
2. **부작용 모듈에서 값을 내보내는 모듈로 바꾼 것.** 6단계에는 export 가 하나도 없어서 `import "./env.js"`
   한 줄을 맨 위에 두는 것으로 순서를 맞췄고, **그 줄이 아래로 내려가면 부팅이 깨졌다.** 지금은 값을
   쓰는 쪽이 import 하므로 순서를 사람이 지킬 일이 없다. 린터가 "안 쓰는 import" 로 보던 문제도 없어졌다.
3. **`throw` 가 아니라 `process.exit(1)`.** 던지면 스택 트레이스가 같이 찍혀 정작 읽어야 할 한 줄이 묻힌다.
   부팅 실패는 버그가 아니라 설정 문제이고, 읽는 사람에게 필요한 것은 어느 값을 고치라는 문장 하나다.

## 6단계에서 무엇이 바뀌었나

원래 9단계 것을 앞당겨 만들었다. `.env` 읽기를 `store/prisma.ts` 안에 두었을 때, `app.ts` 의 import
목록에서 `auth/tokens.ts` 쪽이 먼저 평가됐고 그 모듈 맨 위의 `JWT_SECRET` 검사가 **아직 비어 있는
`process.env`** 를 보고 `Error: JWT_SECRET 이 없습니다` 로 죽었다.

`.env` 에는 그 값이 멀쩡히 있었다. **값이 없던 것이 아니라 아직 안 읽혔던 것**이고, 이 차이는
로그만 봐서는 보이지 않는다. 읽는 일을 저장소 모듈의 부속에서 꺼내 별도 모듈로 만든 것이 그때의 수정이다.

## 9단계에서 무엇이 바뀌었나

이름만 보던 검사가 zod 스키마로 **전면 교체**됐다. 실제로 어긋나게 해 넷을 확인했고 전부 `exit 1` 이다.

| 넣은 값 | 나온 줄 |
|---|---|
| 짧은 `JWT_SECRET` | `32자 이상이어야 합니다. openssl rand -hex 32` |
| 형식 아닌 `DATABASE_URL` | `postgresql://… 형태의 주소여야 합니다.` |
| `PORT="팔천"` | `숫자여야 합니다.` |
| 아무것도 없음 | 두 항목을 한꺼번에 보고 |

`.env` 없이 환경변수만 주입한 기동도 확인했다(`/health` 200). 회귀 **40 통과 · 0 실패**, `tsc`·`eslint` 오류 0.

## 직접 해 볼 것

1. `JWT_SECRET` 을 16자로 줄이고 띄운다 → 이유 한 줄과 함께 죽는다. `echo $?` 로 `1` 을 확인한다 —
   플랫폼은 이 코드를 보고 배포 실패를 판정한다.
2. `DATABASE_URL` 과 `JWT_SECRET` 을 **둘 다** 지우고 띄운다 → 두 줄이 한꺼번에 나온다. 하나씩 던졌다면
   고치고 띄우기를 두 번 반복했을 것이다.
3. `PORT=` 를 빈 값으로 두고 띄운다 → `coerce` 만 있었다면 `0` 번 포트를 들었을 값이다. `min(1)` 이
   무엇을 막는지 메시지로 확인한다. `min(32)` 를 지우고 짧은 키로 띄워 보면 반대로 서버가 멀쩡히 뜬다.
