# 5문서 — 화면 디자인

`web/src/presentation/styles/tokens.css` 에 값으로 박혀 있는 결정들의 근거다.
값을 바꾸려면 여기를 먼저 고치고 토큰을 맞춘다.

## 무엇을 만드는 화면인가

한글 게시판이다. 사람이 이 화면에서 하는 일은 둘뿐이다 — **제목을 훑고, 글을 읽는다.**
그 둘을 돕지 않는 것은 전부 뺀다. 카드, 그림자, 아이콘, 배지, 그러데이션을 쓰지 않는다.

## 색 — 다섯

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--paper` | `#FFFFFF` | 바탕 |
| `--ink` | `#000000` | 제목, 작성자 이름 |
| `--body` | `#3D3D3D` | 본문 |
| `--muted` | `#8A8A8A` | 날짜, 댓글 수, 보조 버튼 |
| `--rule` | `#E8E8E8` | 목록 구분선 |
| `--seal` | `#CC2E1E` | **누를 수 있는 것에만** |

제목은 진짜 검정(`#000000`)을 쓰고 본문은 확실히 연한 회색을 쓴다.
둘 사이를 `#111` 과 `#222` 처럼 애매하게 두면 위계가 생기지 않고 화면이 흐려지기만 한다.

악센트가 하나뿐인 것이 이 디자인의 규칙이다. **인주 붉은색**은 한글 문서에 찍는 도장에서 가져왔고,
버튼·포커스 테두리·내가 쓴 글의 작성자 이름에만 나타난다. 그래서 화면에서 붉은 것이 보이면
그것은 언제나 "내가 관여할 수 있는 것" 이다.

다크 모드는 종이와 잉크를 뒤집고 인주를 밝은 쪽(`#FF6A55`)으로 옮긴다.
`prefers-color-scheme` 만 본다 — 토글을 두지 않는다. 읽기 도구에 설정을 하나 더 만들 이유가 없다.

## 활자 — 둘

| 역할 | 서체 | 쓰는 곳 |
|---|---|---|
| 읽는 글 | **Hahmlet** (세리프) | 글 제목, 본문, 댓글 본문 |
| 조작하는 것 | **Gothic A1** (산세리프) | 버튼, 입력 라벨, 날짜, 개수 |

역할이 다르면 활자도 다르다. 읽는 것은 세리프로 앉히고, 누르는 것은 산세리프로 세운다.
한국 웹의 기본값인 Noto Sans KR·Pretendard 를 피한 것은 그것이 나빠서가 아니라,
어느 사이트에나 있어서 이 화면만의 인상을 만들지 못하기 때문이다.

크기는 1.333 비율로 여섯 단만 쓴다.

```
0.8125rem  메타 (날짜, 댓글 수)
0.875rem   버튼·라벨
1rem       기본
1.0625rem  본문 읽기        ← 세리프, line-height 1.9
1.5rem     목록의 글 제목
2.3125rem  상세의 글 제목
```

본문 줄 길이는 `62ch` 로 묶는다. 한글은 글자 폭이 일정해서 줄이 길어지면 눈이 돌아올 자리를 잃는다.
세리프 본문의 줄 간격을 1.9 로 넓게 준 것도 같은 이유다.

### 크기 토큰은 Tailwind 테마에 등록해야 한다

`text-[var(--t-title)]` 로 쓰면 크기가 적용되지 않는다. Tailwind 는 대괄호 안의 `var()` 를
**색으로 해석**해서, 글자 크기로 쓰려던 선언이 조용히 버려진다. 에러도 경고도 나지 않고
글자가 기본 크기로 남을 뿐이라 알아채기 어렵다.

그래서 `globals.css` 의 `@theme inline` 에 `--text-meta`·`--text-title`·`--text-display` 로 등록하고
`text-title` 같은 진짜 유틸리티로 쓴다. 색 토큰(`text-[var(--ink)]`)은 어차피 색이므로 그대로 둬도 된다.

이름을 지을 때 색과 크기가 겹치지 않게 한다. 색에 `--color-body` 가 있으므로 크기 쪽에는
`--text-body` 를 두지 않았다 — 겹치면 `text-body` 가 둘 중 무엇인지 알 수 없다.

## 레이아웃

720px 한 컬럼. 목록은 행이고, 행 사이에는 1px 선만 있다.

```
┌────────────────────────────────────────┐
│ 게시판                         로그인  │  헤더 (13px, 아래 선 하나)
├────────────────────────────────────────┤
│                                        │
│ 글                        [ 글 쓰기 ]  │
│ ───────────────────────────────────    │
│ BFF 를 지나온 글               댓글 3  │  ← 24px 세리프 / 13px 회색
│ 웹    9월 22일                         │  ← 13px 회색
│ ───────────────────────────────────    │
│ 두 번째 글                             │  ← 댓글 0 이면 숫자를 아예 안 쓴다
│ 남    9월 21일                         │
│                                        │
│              [ 더 보기 ]               │
└────────────────────────────────────────┘
```

**제목만 크다.** 나머지는 전부 13px 회색으로 물러난다. 훑는 눈이 제목 줄만 따라가면 되게 만든 것이다.

메타를 가운뎃점(`·`)으로 잇지 않는다. 작성자와 날짜는 공백으로 띄우고, 댓글 수는 행의 반대쪽 끝에 둔다.
날짜는 올해 글이면 연도를 뺀다 — 목록에서 같은 숫자가 스무 번 반복되면 그것이 제목을 가린다.

## 움직임

호버로 움직이는 것은 하나다. **제목에 인주색 밑줄이 그어진다.**
카드가 떠오르거나 그림자가 짙어지거나 색이 번지는 것은 없다.
`prefers-reduced-motion` 을 존중해 전환을 끈다.

## 접근성

- 포커스는 인주색 2px 테두리로 항상 보인다. `outline: none` 을 어디에도 쓰지 않는다.
- 본문 `#3D3D3D` 대 흰 바탕의 명도 대비는 10:1 을 넘는다. 메타 `#8A8A8A` 는 3.5:1 정도라
  13px 보조 정보에만 쓰고 본문에는 쓰지 않는다.
- 글쓰기 화면의 제목 입력은 라벨을 눈으로 숨기고(`sr-only`) 자리표시자로 대신한다.
  스크린 리더에는 라벨이 그대로 읽힌다.

## 글

- 버튼은 무슨 일이 일어나는지 말한다. "제출" 이 아니라 "글 올리기", "댓글 달기" 다.
- 같은 동작은 화면이 바뀌어도 같은 이름을 쓴다.
- 빈 화면은 분위기가 아니라 방향이다. "아직 글이 없습니다." 아래에 "첫 글 쓰기" 를 둔다.
- 에러는 사과하지 않는다. 무엇이 잘못됐고 어떻게 하면 되는지만 말한다 —
  "내가 쓴 글만 지울 수 있습니다.", "다시 로그인해 주세요."
